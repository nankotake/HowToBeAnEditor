# 开发路线图与里程碑

> 版本：v0.1 · 2026-08-05  
> 原则：**先跑通一个完整订单循环，再谈内容量**。所有里程碑都以"可玩、可试、可被骂"为准。

---

## 1. 里程碑总览

| 阶段 | 名称 | 周期（估） | 核心目标 |
| --- | --- | --- | --- |
| M0 | 概念验证原型 | 1–2 周 | 时间线可拖素材 + 1 单完整闭环 |
| M1 | 垂直切片 | 3–4 周 | 3 单 + 需求/评分/反馈 + 异常机制雏形 |
| M2 | 编辑器打磨 | 3–4 周 | 撤销重做、转场、字幕、调色、播放器 |
| M3 | 内容生产 | 6–8 周 | 订单库、客户、素材资产批量产出 |
| M4 | 经营系统 | 4–6 周 | 工作室、员工、流水线、经营压力 |
| M5 | 主线与结局 | 4–6 周 | 8–12 章主线、结局分支、回看系统 |
| M6 | 打磨与原生发布 | 4–6 周 | 教程、性能、存档、原生打包（Tauri/Capacitor 或迁 Godot 4，由 demo 验证结论决定） |

总计约 **6–9 个月**（1–2 人全职 + 外包）；如果是业余小团队，建议按 1.5–2 倍周期规划。

---

## 2. 各阶段详细交付与验收

### M0 概念验证（最重要）

交付物：

- 一个可玩页面：素材库 + 预览 + 时间线（单轨即可）
- 支持：拖入、排序、裁剪 in/out、删除、播放预览
- 1 个完整订单：需求文本 → 剪辑 → 导出动画 → 评分 → 客户反馈 → 加钱
- 基础存档：项目 JSON 存 IndexedDB

验收标准：

- 自己玩 3 遍不觉得操作反人类
- 找 2 个非开发者试玩，能无教学完成"接单→交付"
- 确认"模拟剪辑"手感成立：拖拽、播放、裁剪的流畅度达标

> 本阶段同时拍板：美术风格、恐怖浓度、平台优先级。

### M1 垂直切片

交付物：

- 需求清单 + 硬/软要求判定 + 满意度评分（含隐藏要求）
- 3 种客户（普通 / 荒诞 / 神秘），3 个订单
- 客户反馈文本系统（好评/差评/拒付/特殊反应）
- 异常系统雏形：至少 3 种异常（多一人、多一帧、倒放低语）
- 标记 / 无视 / 剪进去 三条路径，各有效果
- 声誉与接单池基础

验收标准：

- 同一订单三种剪法得到三种不同反馈，且都有乐趣
- 异常发现有"吓一跳/起鸡皮疙瘩"的效果
- 打出一份 15 分钟的试玩录屏

### M2 编辑器打磨

交付物：

- 多轨（V1/V2/A1/字幕）、撤销重做、转场、变速、倒放、静音、字幕
- 调色页（简化版）、交付页（导出预设 + 动画）
- 播放器：播放/暂停/逐帧/跳转、异常帧叠加渲染

验收标准：

- 连续 30 分钟剪辑无崩溃、无状态错乱
- 撤销重做 100 次操作后时间线与初始一致

### M3 内容生产

交付物：

- 订单模板系统 + 参数随机（文本、素材、要求组合）
- 常驻客户 10 位 + 一次性订单 40–60 单
- 素材资产批量产出（200+ 段）+ 异常复用件 30+

验收标准：

- 连续接 20 单无重复感（组合去重验证）
- 需求文案笑点抽查通过（找 3 人读文案，平均笑 1 次以上）

### M4 经营系统

交付物：

- 工作室页面：招聘、工资、房租、设备、平台抽成
- 分派系统：把"粗剪/字幕/调色/配音/审片"环节交给员工
- 员工属性与事件（摸鱼、搞砸、发现异常并报告）
- 流水线与批量单

验收标准：

- 经营节奏不拖累剪辑乐趣（分派后玩家仍有事可做）
- 员工异常报告机制触发过至少 1 次主线钩子

### M5 主线与结局

交付物：

- 神秘客户线 8–12 章（以订单为章节载体）
- 4 个结局 + 分支记录
- 项目档案 / 回看 / 复剪 / 隐藏收集

验收标准：

- 从零通关一次，主线逻辑自洽（含所有异常线索闭环）
- 三种主要玩法路径（正经/恶搞/观察）都能通关

### M6 打磨与发布

交付物：

- 新手引导（不打断体验的隐形教程）
- 移动端适配 + 性能降级
- 存档兼容、云存档（可选）、隐私合规
- 上线渠道：网页（Vercel/Netlify）→ PWA → 视情况小游戏/套壳

验收标准：

- 新玩家首局 5 分钟内进入剪辑心流
- 低端手机 + 20 素材项目保持 30fps 以上

## 3. 团队与分工建议

| 规模 | 组合 | 说明 |
| --- | --- | --- |
| 最小（3 人） | 程序 1 + 设计 1 + 文案 1 | 美术音频外包，M0–M1 完全可行 |
| 标准（5 人） | 程序 2 + 设计 1 + 美术 1 + 文案 1 | M3 内容产能是瓶颈，多一人产能翻倍 |
| 完整（7 人） | + 音频 1 + 运营/测试 1 | 冲刺上线期配置 |

关键提示：**内容产能是本项目最大瓶颈**（需求文案、客户对话、素材量），提前规划模板化生产，避免在 M3 阶段手工堆量。

## 4. 风险清单与对策

| 风险 | 概率 | 影响 | 对策 |
| --- | --- | --- | --- |
| 时间线 UI 复杂度失控 | 高 | 高 | M0 就锁死工具范围；命令模式先行；不做 Resolve 全功能 |
| 内容量过大做不完 | 高 | 高 | 订单模板化 + 异常复用 + 先做 15 单上线验证 |
| 恐怖元素过审/口碑反噬 | 中 | 中 | 恐怖浓度可调开关；以氛围为主；喜剧兜底 |
| 剪辑玩法变成"填写清单" | 中 | 高 | 评分带随机与客户偏好，避免唯一解；恶搞路径必须有正反馈 |
| 经营系统拖累节奏 | 中 | 中 | 经营只做"分派环节"，不引入复杂生产链 |
| 单人产能不足 | 中 | 高 | 素材程序化生成；文案 AI 草稿 + 人工润色 |

## 5. 下一步行动（建议顺序）

1. 拍板设计决策：恐怖浓度、美术风格、正式名字（桌面优先已基本确定，移动端是否首发待定）
2. 用 Figma 出一版 Resolve 风格工作台线框稿（对照设计文档第 10 节）
3. 开始 M0 原型：我这边可以直接搭一个可运行的 H5 编辑工作台骨架
4. M0 跑通后做一次原生承载冒烟验证：Tauri 打包桌面 demo、Capacitor 装真机，验证"一套代码两端跑"是否成立
5. 写 3 个测试订单的完整文案与素材清单，作为垂直切片内容
